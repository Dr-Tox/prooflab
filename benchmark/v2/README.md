# ProofLab v2 linguistic challenge set

Run `npm run benchmark:v2`; run `npm run benchmark:v2 -- --paragraphs` for the supplementary paragraph audit. Both use actual Harper 3.0.0 WASM and the production adapter, scientific policy, aggregation and revision-checked edit functions. No mock results, network NLP or document telemetry are involved. Synthetic test sentences and their raw lints are intentionally committed as engineering artifacts.

## Metrics and limits

Each positive case has one expected defect group, sometimes requiring coordinated edits. Detection counts a case once when a diagnostic overlaps its changed source interval, expanding insertion-only references to the source token. Warning-only dated-perfect cases require the appropriate contextual rule. Classification is evaluated separately as the application's coarse Grammar category; this is not a fine-grained POS/dependency accuracy metric. Scientific/style warnings are not treated as agreement errors.

Precision is TP cases / (TP cases + extraneous Grammar cards), recall is TP cases / positive cases, and F1 is their harmonic mean. This mixed case/card precision is a diagnostic proxy: it is not token-level precision on unconstrained documents. All-category and Grammar false-positive case rates are reported independently on controls. Detection/precision alone do not establish correction quality.

Replacement quality compares individual alternatives with the expected source-aligned token interval, only where input/reference token counts align. It reports that restricted denominator; unequal-length coordinated edits are assessed by complete-sentence outcomes instead. First-suggestion correctness uses the first alternative of each comparable card. Complete correction requires an **exact accepted full sentence/paragraph**, using a bounded oracle over actual nonoverlapping suggestions (up to five alternatives, five cards, 2,048 search nodes). First-choice complete correction applies first alternatives in descending source order, skipping overlaps. It is a static offered-actions audit, not automatic accept-all or a simulated user strategy. Every action still uses real transaction validation. The browser reanalyzes after individual accepts.

Multiple or overlapping cards do not increase successful detection counts. Exact-span identical-alternative duplicates are reported separately; semantic duplicates outside this definition still require review. Forbidden outcomes, numeric-token changes and lost hedges form a **limited harmful-change proxy**, not a meaning-preservation proof. A manual audit found the paragraph-set `microbeads → microbe's / microbes` alternatives scientifically harmful despite a zero numeric/hedge proxy. All four alternatives across the positive/control pair are unsafe (4/13 comparable proposals); 2/30 paragraph cases expose this risk. Do not report “0% harmful corrections” from the proxy. No broad suppression or vocabulary additions were tuned to hide this fresh failure.

Performance is single-process Node/Vite-node wall time with diagnostics enabled, setup recorded separately. `process.memoryUsage()` is sampled after retaining reports: RSS/external allocations include WASM, harness, JIT and raw-lint data. These are not isolated engine peaks or browser memory. Timing and RSS variation do not prove an optimization. Browser tests exercise actual Chromium; other browsers, operating systems, extensions and real journal manuscripts require additional validation. There is no Microsoft Word comparison.

## Reproduce the baseline

Archive `0c3b269` to a separate directory, provide the same lockfile-installed `node_modules`, and use the checked-in runner with only its `Proofreader`/model imports redirected to that archived source. Set `SOURCE_COMMIT=0c3b269` and pass `--baseline` (and optionally `--paragraphs`). The reports record source revision, Node/CPU/platform, corpus hash, actual raw lints, latency and process memory. Do not check out old source over uncommitted work or overwrite historical first-evaluation files.
